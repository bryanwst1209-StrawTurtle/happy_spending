# 待归类设计

日期:2026-10-16 · 项目:happy_spending
上位文档:`2026-10-13-apple-pay-auto-record-design.md`(商户记忆 §3、§4.3)、`2026-10-15-screen-and-notification-auto-record-design.md`(冲突时以本文为准)

## 1. 目标与范围

自动记下的账常常没有分类("未分类"):没学过的商户、通知记下的账(没有商户名)、商户名没识别出来的屏幕识别账。现在只能一笔笔点进编辑页去改,而且"按商户记住分类"这个功能藏得很深。

**做:**

- 账单页顶部的"待归类 N 笔"入口,账单页签图标上的数字角标。
- 归类面板:一次一笔,点一两下归好,自动跳到下一笔。
- 归好一笔有商户的自动账时,记住这个商户,并把同一商户其他未分类的支出一起归好。
- 编辑页改自动账分类时,同样把同商户的未分类支出一起归好。

**不做:**

- 撤销:归错了点进那笔账改一下(改的同时会更新商户记忆)。
- 记住"跳过":跳过只在这一次打开面板时有效。
- 商户记忆的管理界面。
- 给没有商户的账推测分类。

## 2. 什么是"待归类"

`kind == .expense` 且 `category == nil` 的账,不分月份,按日期从早到晚、同一天按记账时间从早到晚排列。

手动记账一定会选分类(记账页总会选中一个),分类只能归档不能删除,所以待归类的账实际上都是自动记下的。收入不算。

## 3. 归类规则

新增 Core 单元 `PendingCategorization`:

- `pending(_ entries: [LedgerEntry]) -> [LedgerEntry]`:从给定的账里挑出待归类的,按 §2 排序。纯函数。
- `assign(_ entry: LedgerEntry, to category: LedgerCategory, in context: ModelContext, now: Date) throws -> Int`:归好一笔,返回**一起归好的其他笔数**。
- `backfill(sameMerchantAs entry: LedgerEntry, in context: ModelContext) throws -> Int`:把与 `entry` 同商户、还没分类的其他支出设成 `entry` 的分类,返回笔数。不保存。

`assign` 的步骤:

1. `entry.category = category`。
2. 如果这笔账是自动账、支出、商户非空、所选分类是支出分类,就调用已有的 `MerchantMemory.learn` 记住"商户 → 分类",然后 `backfill`。否则只归这一笔,返回 0。
3. 一次 `context.save()`。保存失败时 `context.rollback()` 撤回本次所有改动,再把错误抛出去。

`backfill` 的规则:

- 商户按已有的 `MerchantKey.normalize` 比较(忽略大小写、多余空白)。
- 只改 `kind == .expense`、`category == nil`、不是 `entry` 本身的账。已经有分类的账不动。
- `entry` 没有分类或没有商户时什么也不做,返回 0。

## 3.1 只记一级分类(2026-10-16 需求更新)

- 商户记忆只存**一级分类**:归到"餐饮 · 午餐"时记住"餐饮"(`assign` 与编辑页的 `learnFromEdit` 都如此)。
- 当前手动选的这一笔保留所选的二级分类;同商户一起归好的其他账归到**一级分类**。
- 以后同一商户的自动账归到一级分类。
- 以前记成二级分类的旧记忆不迁移,查找时按它的一级分类算(`MerchantMemory.categoryID`)。

## 4. 界面

### 4.1 入口

- 账单页列表最上面一行:"待归类 N 笔 ›"(N 为所有月份的待归类笔数)。N 为 0 时这一行不显示。点它打开归类面板。
- 账单页签图标显示数字角标 N,为 0 时不显示。
- 数字跟着数据实时变化(由 SwiftData 查询驱动)。

### 4.2 归类面板

以 sheet 弹出,标题"待归类",右上角"跳过"。一次显示一笔,从最早的开始:

- 上半部分:金额、商户(没有商户就显示备注)、日期、来源(屏幕识别 / 通知 / Apple Pay)。
- 下半部分:复用记账页的 `CategoryPicker`(常用分类、一级分类格子、二级分类条),只显示支出分类。

选择方式:

- 点一个**没有未归档二级分类**的一级分类,或点任意二级分类、常用分类里的二级分类:立即归好,显示下一笔。
- 点一个**有二级分类**的一级分类:下面出现二级分类条,并出现按钮"就用『<一级分类名>』";点二级分类或这个按钮才归好。
- "跳过":这一笔本次不处理,显示下一笔。
- 同商户一起归好时,在面板顶部短暂提示"已同时归类 2 笔 示例小吃"(约 2 秒)。一起归好的账不再单独出现。
- 没有下一笔(全部归好或都跳过了)时面板自动关闭。
- 保存失败:弹出错误提示,停在这一笔。

### 4.3 编辑页

`EntryEditSheet` 保存时,如果 `MerchantMemory.learnFromEdit` 学习了(自动账改了分类),再调用 `backfill`,和本次编辑一起保存。`backfill` 返回大于 0 时,先弹出提示"已同时归类 N 笔 <商户>",点"好"后再关闭编辑页;为 0 时直接关闭。

### 4.4 帮助页

"分类怎么来的"一节补一句:自动记下、还没有分类的账会出现在账单页的"待归类"里,归好一次同一商户以后自动沿用。

## 5. 测试方案

Swift Testing,SwiftData 用内存容器。

- **待归类列表**:只含没有分类的支出;跨月份;按日期、再按记账时间从早到晚;不含收入、不含已有分类的账、不含有分类的手动账。
- **assign**
  - 有商户的自动账:设好分类、学到商户记忆、同商户(仅大小写或空白不同)的其他未分类支出一起归好,返回笔数。
  - 同商户已有分类的账不动;同商户的收入不动。
  - 没有商户的自动账、手动账:只归这一笔,不学习,返回 0。
  - 归好后,同一商户再通过 `AutoEntryRecorder` 记一笔,直接用这个分类(整条链路)。
- **backfill**:没有分类或没有商户时返回 0,不改任何账;编辑页路径(先 `learnFromEdit` 再 `backfill`)把同商户未分类账一起归好。
- **模拟器手动检查**:入口与角标的数字、面板逐笔归类、二级分类与"就用『X』"、跳过、同商户提示、全部处理完自动关闭、编辑页的提示。

## 6. 真机验证清单

1. 屏幕识别、通知各记一笔没分类的账后,账单页签出现角标,账单页出现"待归类 N 笔"。
2. 在面板里归好一笔有商户的账,同商户的其他未分类账一起归好并有提示;再在该商户付一笔,自动记下时直接带分类。
3. 没有商户的账(通知记的)归类后,不会影响其他账。
