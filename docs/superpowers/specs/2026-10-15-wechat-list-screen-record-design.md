# 微信支付消息列表的屏幕识别记账设计

日期:2026-10-15 · 项目:happy_spending
上位文档:`2026-10-15-screen-and-notification-auto-record-design.md`(本文在它的"屏幕识别"上新增一种页面,并修改微信的去重方式;冲突时以本文为准)

## 1. 目标与范围

在微信里打开"微信支付"消息列表,按一下操作按钮(或轻点背面),**把这一屏上所有完整的支付卡片都记下来**,不用逐笔点进账单详情。

**做:**

- 新增一种屏幕页面:微信支付消息列表。
- 微信的去重从"单号"改为"金额 + 精确到分钟的时间",让同一笔在列表页和详情页记过都能认出来。
- 一次记多笔时,提示里说清记了几笔、跳过几笔。
- 帮助页、手动检查清单补上列表页的用法。

**不做:**

- 不从单号里推算日期。
- 支付宝的消息列表。
- 跨屏或跨月份的批量补记:一次只看当前这一屏。
- 不迁移已有数据:已经用旧标识记下的微信账(目前都是测试数据)由用户删掉重记。

## 2. 真实样本里看到的

样本来自作者的手机,经"提取图像中的文字"识别:

- `¥` 被识别成 `·`,后面常带空格:`· 9.90`、`·147.70`。
- 时间标签整行出现:`13:00`、`昨天18:23`(可能没有空格)、`星期六 11:01`。列表最早只显示到约一周前。
- 卡片有三种:普通支付("使用…支付")、自动续费("通过…自动续费",下面还有"续费项目""开通账号"等额外行)、转账("微信支付凭证"…"收款方""交易状态")。
- 自动续费卡片识别后**行序是乱的**:"续费项目""开通账号"两个标签在金额前面,对应的值在后面。
- 瑞幸的商户行("luckincoffee瑞幸咖啡")**整行没有被识别出来**。
- 屏幕最上面常有一张被截断的卡片(只剩"收款方 / 交易状态 / 查看账单详情")。
- 每张卡片以"账单详情＞"或"查看账单详情"结束。

## 3. 列表页解析

新增 `WeChatListParser`,只负责列表页;认不出是列表页时返回 nil,由原来的 `ScreenTextParser` 接着处理单页。

### 3.1 判断是列表页

文字里有一行**恰好是** `微信支付`,并且它下面至少有一行时间标签。这一行以上的内容(状态栏时间等)全部忽略,所以状态栏的 `16:40` 不会被当成卡片时间。

### 3.2 时间标签

整行(去掉首尾空白)匹配下面任一格式才算时间标签,按当前时间 `now` 和日历换算成具体日期时间(精确到分钟):

| 格式 | 例子 | 换算 |
|---|---|---|
| `HH:mm` | `13:00` | 今天 |
| `昨天 HH:mm`(空格可有可无) | `昨天18:23` | 昨天 |
| `星期X HH:mm`(X 为一到日、天) | `星期六 11:01` | 往前数 2 到 8 天里是星期X 的那一天(这 7 天里每个星期X 恰好出现一次;不会是今天或昨天) |
| `M月d日 HH:mm` | `10月8日 18:23` | 今年;如果比 `now` 晚,算去年 |
| `yyyy年M月d日 HH:mm` | `2025年10月8日 18:23` | 照写 |

时、分越界(如 `25:00`)或日期不存在的,不算时间标签。

### 3.3 切出卡片

从 `微信支付` 那一行往下逐行看:

1. 遇到时间标签:记下"当前时间",并开始新的一段。
2. 遇到以 `账单详情` 或 `查看账单详情` 开头的行:当前这一段结束。这一段同时满足下面三条才是一张**完整卡片**:
   - 前面出现过时间标签(当前时间不为空);
   - 段内有一行金额:整行是 `[¥￥Y·•]` 加数字(如 `· 9.90`、`¥0.20`);
   - 段内有支出标志行:以"使用"开头且含"支付",或以"通过"开头且含"自动续费""扣费""支付"之一,或整行是"微信支付凭证"。
   结束后接着往下看,新的一段沿用"当前时间",直到遇到下一个时间标签(几笔支付挨得很近时,微信只显示一个时间标签)。
3. 其余行归入当前段。

由此:

- 第一个时间标签之前的内容(顶部被截断的卡片)没有时间,跳过。
- 最下面没有"账单详情"收尾的段(底部被截断)不会结束,跳过。
- 退款、收款这类没有支出标志的卡片跳过。

### 3.4 每张卡片的字段

- **金额**:金额行的数字,用现有 `AmountText` 解析;解析失败(为 0、超上限)的卡片跳过。
- **商户**:支出标志行的上一行(在本段内)。如果那一行是以下之一,或清理装饰字符后为空,就没有商户:`续费项目`、`开通账号`、`收款方`、`交易状态`、`微信支付凭证`,操作行 `微信代扣`、`对订单有疑惑`、`进入商家小程序`(商户行没识别出来时,上一张卡的这些残余行会紧挨在支出标志上方),单个字符(如 logo 被识别成的 `收`)。
- **备注**:商户,没有商户就是"微信"。
- **日期**:卡片的时间。
- **来源**:屏幕识别。
- **去重标识**:见 §4。
- **平台分类**:无。分类按现有规则走商户记忆,没有就是"未分类"。

## 4. 去重

### 4.1 微信的标识

`WeChatPaymentKey.make(cents:time:calendar:)` = `微信|<金额分>|<yyyy-MM-dd HH:mm>`,作为 `PaymentRecord.orderRef` 传入,写库前照旧哈希成 `orderRefHash`。数据模型不变。

| 页面 | 标识 |
|---|---|
| 微信·消息列表的卡片 | 金额 + 卡片时间 |
| 微信·账单详情页,时间读出来了 | 金额 + 页面上的支付时间/转账时间(去掉秒) |
| 微信·账单详情页,时间没读出来 | 单号(和以前一样) |
| 微信·支付成功页 | 无(页面上没有时间) |
| 支付宝 | 不变 |

商户不放进标识:列表页可能认不出商户(瑞幸),放进去两边就对不上。

已知会漏掉的情况(都很少见):

- 同一分钟里金额完全相同的两笔不同支付,只记一笔。
- 一个时间标签下挂了好几笔时,后面几笔用的是第一笔的时间,和它们详情页上的时间可能不在同一分钟,两边各记一次就会重复。
- 消息时间偶尔比支付时间晚一分钟,同上。

### 4.2 重复提示

标识不再一定是单号,重复时的提示从"已记过这一笔(单号相同)"改为"已记过这一笔"。

## 5. 入账与提示

`PaymentCapture.recordScreenText` 先交给 `WeChatListParser`:

- 返回 nil:不是列表页,走原来的单页流程,行为不变。
- 返回空数组:是列表页但没有完整卡片,抛错 `PaymentCaptureError.noCompleteCard`,提示"这一屏没有完整的支付记录"。
- 返回若干笔:按从上到下的顺序逐笔调用 `AutoEntryRecorder.record`。同一屏里标识相同的,第二笔会被判为重复。

其中一笔保存失败时抛错;前面已经保存的留在库里,再按一次会被去重,不会重复。

返回给快捷指令的提示(`新`=新记的笔数,`重`=判为重复的笔数,金额是新记的合计):

| 情况 | 提示 |
|---|---|
| 新 1、重 0 | 沿用单笔提示,如 `已记 ¥81.00 · 地摊串热辣滚烫` |
| 新 ≥ 2、重 0 | `已记 2 笔,共 ¥136.70` |
| 新 ≥ 1、重 ≥ 1 | `已记 1 笔 ¥81.00,1 笔已记过` / `已记 2 笔,共 ¥136.70,1 笔已记过` |
| 新 0、重 1 | `已记过这一笔` |
| 新 0、重 ≥ 2 | `这一屏的 2 笔都记过了` |

`CaptureResult.recorded` 为"新 ≥ 1"。

## 6. 界面与文档

- 帮助页"② 屏幕识别"第 4 步改为:停在"支付成功"页、"账单详情"页,或微信支付消息列表上时按一下;在列表上按会记下这一屏所有完整的支付。
- 手动检查清单新增列表页的真机检查项(§8)。
- 快捷指令动作本身不变。

## 7. 测试方案

Swift Testing,SwiftData 用内存容器。夹具取自真实样本,单号、卡号尾号换成假值,版式和噪音原样保留。

- **列表解析**
  - 样本一(`now` = 2026-10-15 16:25,星期四):顶部截断的转账卡跳过;山姆 ¥147.70 → 10/14 18:23,商户"山姆会员商店"(夹具里换成示例名);地摊 ¥55.00 → 10/15 13:00。
  - 样本二(`now` = 2026-10-15 16:40):瑞幸 ¥9.90 → 10/10 11:01,没有商户、备注"微信";地摊 ¥81.00 → 10/10 12:41。
  - 底部截断(有时间和商户,没有金额或"账单详情")跳过。
  - 状态栏时间、"微信支付"之上的内容不被当成时间标签。
  - 一个时间标签下两张卡片,都用这个时间。
  - 没有支出标志的卡片(退款、收款)跳过;只有截断卡片时返回空数组。
  - 转账卡片:按视频里看到的版式构造的夹具(标明不是识别原文),商户为空、备注"微信"。
  - 不是列表页(详情页、成功页、随便的文字)返回 nil。
- **时间标签**:五种格式;`昨天18:23` 无空格;跨年(1 月 2 日看到 `12月30日` → 去年);星期X 不会落到今天或昨天;越界时间不算标签。
- **去重**
  - 同一屏按两次:第二次 `这一屏的 N 笔都记过了`,不新增。
  - 先记山姆的详情页,再按列表页:山姆判为重复,地摊新记。
  - 详情页时间读不出来时用单号,按两次只记一笔。
  - 同一屏两张金额和时间都相同的卡片只记一笔。
- **提示**:§5 表里每种情况一条;`noCompleteCard` 的提示文字。
- 已有测试照常通过;断言"已记过这一笔(单号相同)"的改为"已记过这一笔"。

## 8. 真机验证清单

1. 在微信支付消息列表上按一下:记下的笔数、金额、日期、商户和屏幕一致,提示文字正确。
2. 一张完整的转账卡片("微信支付凭证")的识别文字顺序与构造的夹具一致(采样后补进测试)。
3. 一个时间标签下挂两笔支付时,两笔都记上。
4. 同一笔先在列表页、再在详情页各按一次(或反过来),只记一笔。
5. 再按一次同一屏,提示"这一屏的 N 笔都记过了"。
6. 滑到只剩截断卡片的位置按一下,提示"这一屏没有完整的支付记录"。
