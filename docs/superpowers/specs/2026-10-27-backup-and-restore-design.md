# 备份与恢复设计

日期:2026-10-27 · 项目:happy_spending
上位文档:`2026-10-10-bookkeeping-app-design.md`(冲突时以本文为准)

## 1. 目标与范围

现在数据只存在手机本地:删掉 app、换手机,数据就没了。已有的"导出 CSV"只有账单本身,分类、图标、商户记忆都不在,也导不回来,不算备份。

本文做的是**不依赖 iCloud 的备份**,免费开发者账号就能用,也适用于不开 iCloud 的用户。以后升级付费开发者账号后再加 iCloud 同步(CloudKit 私有数据库,存在每个用户自己的 iCloud 里),那是另一份设计,本文的备份文件留作兜底。

**做:**

- 一个完整的备份文件格式。
- 设置 → "备份与恢复":导出备份、从备份恢复、自动备份到用户选的文件夹。
- 恢复是**整体替换**:先自动存一份"恢复前备份",再在一次保存里换成备份里的数据。
- 自动备份:每天第一次打开 app 时写一份,只保留最近 7 份。
- 长期没备份时的小红点提醒。

**不做:**

- iCloud 同步(要付费开发者账号,另行设计)。
- 合并恢复(保留现有数据、只加备份里没有的):情况多、容易出意外,用户选了整体替换。
- 备份文件加密:文件只在用户自己的设备、文件夹、网盘之间流转。
- 从别的记账 app 导入。

## 2. 备份内容与文件格式

一个 JSON 文本文件,文件名 `HappySpending 备份 yyyy-MM-dd.json`(自动备份同一天只有一份,手动导出同一天重名时加时间 `yyyy-MM-dd HHmmss`)。

```
{
  "app": "HappySpending",          // 用来认出是不是本 app 的备份
  "formatVersion": 1,              // 格式版本,以后数据结构变了递增
  "createdAt": "<ISO 8601>",
  "categories": [ { id, name, symbolName, iconData(base64,可空), colorHex, kind, sortOrder, isArchived, parentID(可空) } ],
  "entries":    [ { id, amountInCents, kind, date, createdAt, note, categoryID(可空), autoSource(可空), merchant(可空), orderRefHash(可空) } ],
  "merchantMemory": [ { merchantKey, categoryID, updatedAt } ],
  "appearance": { "choice": "system | image | preset:<id>", "opacity": 0.4, "image": "<base64 JPEG,可空>" }
}
```

- 日期统一存 ISO 8601;账单日期按现有约定是"那一天 GMT 0 点"的瞬间,原样存取。
- 体积:每笔账约几百字节,一年约 1 MB;有背景图再多几百 KB。
- 编码、解码放在 Core(`Backup` 相关类型),用内存数据库测。

## 3. 设置页"备份与恢复"

设置页新增一节"备份与恢复"(和"外观"同级),三项:

1. **导出备份**:生成文件后弹出系统分享面板(存到"文件"、AirDrop、发微信等)。记录"上次手动导出"的时间。
2. **从备份恢复**:用系统文件选择器选一个 `.json` 文件 → 检查(§4) → 预览确认 → 替换(§5)。
3. **自动备份**:
   - 未设置时显示"选择备份文件夹";用系统文件夹选择器选一个 app 外面的文件夹("我的 iPhone"里的文件夹、接入"文件"的网盘目录等)。app 记住这个文件夹的访问权限(security-scoped bookmark)。
   - 设置后显示"上次自动备份:今天 09:12"、"更换文件夹"、"关闭自动备份"。
   - 失败时显示原因和"重新选择文件夹"(§6)。

**提醒**:自动备份没开,且距离上次手动导出超过 30 天(或从没导出过、且已有账单)时,设置页签和"备份与恢复"这一行显示小红点。

## 4. 恢复前的检查

读取文件后先检查,全部通过才进入预览;任何一条失败都不改动手机上的数据。

| 情况 | 结果 |
|---|---|
| 不是 JSON、缺少 `"app": "HappySpending"`、必需字段缺失 | 拒绝:"这不是 Happy Spending 的备份文件" |
| `formatVersion` 大于当前 app 支持的版本 | 拒绝:"这个备份来自更新版本的 app,请先升级再恢复" |
| 账单或分类编号重复;二级分类的 `parentID` 指向不存在的分类或指向二级分类 | 拒绝:"备份文件已损坏" |
| 账单的 `categoryID` 指向不存在的分类 | 这笔账按"未分类"恢复,结果里说明"有 N 笔账的分类已不存在,已归为未分类" |
| 商户记忆指向不存在的分类 | 丢弃这条记忆(查找时本来也会忽略) |
| `appearance.choice` 认不出 | 按"默认"(沿用 `BackgroundChoice(stored:)` 的规则) |

检查通过后显示预览:备份时间、账单笔数、账单日期范围、分类个数,确认按钮"替换现有数据"。

## 5. 替换过程

1. 先把当前数据导出成"恢复前备份":设置了自动备份文件夹时写进那里(文件名 `HappySpending 恢复前备份 yyyy-MM-dd HHmmss.json`,不计入 7 份的轮换);没设置时写在 app 自己的目录,"备份与恢复"里可以再导出它。这一步失败就停止,什么都不动。
2. 在同一个 `ModelContext` 里删除全部账单、分类、商户记忆,插入备份里的全部内容,**一次 `save()`**。任何一步出错就 `rollback()`,手机上的数据保持原样,提示"恢复失败,数据未改动"。
3. 成功后写入外观设置(背景选择、浓淡、图片文件),提示"已恢复 N 笔账"。界面由 SwiftData 查询自动刷新。
4. 默认分类只在"一个分类都没有"时写入(现有 `seedIfNeeded`),恢复后以备份里的分类为准;备份里本来就没有分类时,下次启动会补上默认分类。

## 6. 自动备份

- 时机:app 回到前台时检查;本地日期里"今天"还没有自动备份过就写一份。打开 app 不等它完成。
- 写入:读数据、编码在主线程(一年约 1 MB,很快),写文件在后台。
- 轮换:写完后在该文件夹里只保留最近 7 份**自动备份**;只看文件名符合 `HappySpending 备份 yyyy-MM-dd.json` 的文件,其他文件(包括恢复前备份、用户自己的文件)一律不动。
- 失败:文件夹不存在、权限失效、网盘断开、空间不足 → 不弹窗,记录"上次失败的原因和时间",在"备份与恢复"里显示并提供"重新选择文件夹"。下次打开 app 再试。

## 7. 测试方案

Swift Testing,SwiftData 用内存数据库;文件相关的用临时目录。

- **往返**:导出再导入到另一个空数据库,账单每个字段、分类层级与图标、商户记忆、外观设置完全一致。
- **拒绝**:不是 JSON、缺 `app` 标识、版本太新、账单编号重复、分类编号重复、二级分类的上级不存在 / 是二级分类 → 都被拒绝,原数据库内容不变。
- **修正**:账单指向不存在的分类 → 恢复为未分类并返回数量;无效的商户记忆被丢弃;认不出的背景选择 → 默认。
- **原子性**:替换中途出错(构造一个保存会失败的情况或在插入前抛错)→ 原数据不变。
- **轮换**:文件夹里有 9 份自动备份、1 份恢复前备份、1 个别的文件 → 只删最旧的 2 份自动备份。
- **何时自动备份**:今天已备份 / 昨天备份 / 从未备份 / 跨午夜(按本地日期)。
- **文件名**:自动备份、手动导出同日重名、恢复前备份三种格式。
- **提醒**:自动备份开着不提醒;没开、30 天内导出过不提醒;没开、超过 30 天或从没导出且有账单 → 提醒。
- **模拟器手动检查**:导出到"文件"、从文件恢复(预览、替换、恢复前备份出现)、选择自动备份文件夹并在第二天(改系统日期)自动生成新备份、删掉文件夹后看到失败提示、小红点。
