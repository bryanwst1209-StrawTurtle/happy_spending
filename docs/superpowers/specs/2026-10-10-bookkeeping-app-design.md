# 记账 App 设计文档(v1)

日期:2026-10-10 · 项目名:happy_spending

## 1. 目标与背景

市面上的记账 app 要么有广告,要么收费。本项目做一个**无广告、免费、干净**的 iOS 记账 app,同时作为学习 iOS 开发的项目。

- 首要用户是作者本人,按自己的需求持续迭代;之后可以给别人用,但不以赚钱为目的。
- 成功标准:
  1. 作者自己愿意每天用。
  2. 打开 app 后两步就能记完一笔(输入金额,点完成)。
  3. 之后加功能时,代码结构不拖后腿。

## 2. 范围

**v1 做:**

- 极速记账
- 账单列表(按月)
- 统计(月/年)
- 两级分类
- 分类管理(新增、重命名、归档/恢复)与自定义分类图标(见 §14)
- CSV 导出(当月 / 全部)

**v1 不做:**

- CSV 导入(原因:其他 app 导出账单需要办理会员,先完成自己的 app,以后再说)
- 多账户与转账
- 预算与超支提醒
- 多币种与汇率
- 云同步(CloudKit 需要付费开发者账号)
- 桌面小组件
- 自定义时间范围、同比环比、导出图表图片
- 复杂的多条件筛选

## 3. 技术选型

- 平台:iPhone,**最低支持 iOS 26**。不做旧系统降级,直接使用 Liquid Glass 相关 API。
- UI:SwiftUI。
- 持久化:SwiftData,纯本地存储。
- 图表:Swift Charts。
- 选图:`PhotosPicker`(不需要相册权限);图片裁剪缩放用 ImageIO,不引入第三方库。
- 无后端、无网络请求、无第三方依赖。
- 测试:Swift Testing,SwiftData 测试使用内存容器。
- 安装:自用通过 Xcode 真机安装(免费账号,证书 7 天过期需重签)。

## 4. 应用结构

四个 Tab:**记账**(默认)、**账单**、**统计**、**设置**。设置页目前只有一个入口:**分类管理**(§14)。导出 CSV 仍放在账单页右上角菜单。

视图中直接使用 SwiftData 的 `@Query`,不额外引入 ViewModel 层。统计聚合与 CSV 生成写成**纯函数**,输入是一批账单,输出是结构化结果,与界面解耦,便于单元测试。

## 5. 数据模型

> 实现命名:`Transaction` 在代码中叫 `LedgerEntry`,`Category` 叫 `LedgerCategory`,避免与 `SwiftUI.Transaction` 及 ObjC 运行时的 `Category` 重名。

### Transaction(一笔账)

| 字段 | 说明 |
|---|---|
| amountInCents | `Int`,单位为分,恒为正数;1234 表示 12.34 元 |
| type | 支出 / 收入 |
| date | 记账日期(只关心日期) |
| createdAt | 创建时间,用于同一天内的稳定排序 |
| note | 备注,可为空 |
| category | 所属分类,可挂在一级或二级分类上 |

### Category(分类)

| 字段 | 说明 |
|---|---|
| name | 名称 |
| symbolName | SF Symbol 图标名(默认图标) |
| iconData | 可选,自定义图标(128×128 PNG);有值时代替 SF Symbol 显示(§14) |
| colorHex | 颜色 |
| type | 支出 / 收入 |
| sortOrder | 排序 |
| isArchived | 是否已归档 |
| parent | 可选,指向一级分类 |

### 规则

- 分类**只有两层**:一级分类没有 parent,二级分类的 parent 必须是一级分类。
- 一笔账可以只挂在一级分类上(例如只选"餐饮"),不强制选二级。
- 分类**只能归档,不能物理删除**,保证历史账单的分类信息不丢失。归档一级分类时,其二级分类一并归档。
- 首次启动预置常用分类,预置内容见 §14.1。
- 单一币种(人民币),金额固定两位小数。

## 6. 记账页

目标:打开后两步完成一笔。

页面从上到下:

1. **支出/收入切换**,默认"支出"。
2. **金额显示**,大号字体,形如 `¥0.00`。
3. **分类选择区**:
   - 顶部一行"常用",放最近最常用的 5 个分类。
   - 下方是一级分类网格(图标加名称)。
   - 点击有二级分类的一级分类,在网格下方展开其二级分类。
   - 默认选中上次使用的分类。
4. **日期与备注**:日期默认今天,可选昨天或任意日期;备注为可选单行输入。
5. **自定义数字键盘**(不使用系统键盘):0–9、小数点、退格、"完成"。键盘本身限制两位小数,并设上限 9,999,999.99,不依赖事后校验。

保存行为:

- 金额大于 0 才能点"完成"。
- 点击后轻震动,提示"已记一笔",表单清空并**停留在记账页**,便于连续记账。
- 日期保留上次选择,不重置为今天,方便补记。

修改与删除:

- 在账单页点某一笔,打开同一个表单进行编辑。
- 左滑删除,不弹确认框,提供几秒的"撤销"提示。

## 7. 账单页

- 顶部"< 2026年10月 >"切换月份,也可点开选择月份。
- 顶部汇总:本月**收入、支出、结余**。
- 列表按日期倒序分组,组标题显示"10月10日 周六"和当天收支小计。
- 每行显示:分类图标、分类名(二级分类显示为"餐饮 · 午餐")、备注、金额。收入显示绿色并带 `+`。
- 搜索框:按备注和分类名匹配,范围限定在当前月份。
- 右上角菜单:**导出当月 CSV**、**导出全部 CSV**。

## 8. 统计页

顶部"月 / 年"切换,内容随周期变化:

1. **汇总卡片**:收入、支出、结余。
2. **支出分类占比**(环形图):默认按一级分类汇总,图下方为列表(分类、金额、占比)。点击一行进入该一级分类详情,按二级分类展开;未选二级的账单归入"未细分"。
3. **趋势图**(柱状图):选"月"时横轴为当月每一天,选"年"时横轴为 12 个月,柱高为支出总额。
4. **收入分类占比**:结构同支出占比,位于其下方,默认折叠。

数据量为个人记账级别(每年数千条),直接在内存中聚合,不做缓存或预计算。

## 9. 视觉:Liquid Glass

- 系统控件(Tab 栏、导航栏、工具栏、按钮)在 iOS 26 上自动呈现 Liquid Glass。
- 自定义视图手动使用 `.glassEffect()`、`GlassEffectContainer`、`.buttonStyle(.glass)`。
- 原则:玻璃用于**浮在内容之上的一层**(控件、导航、悬浮卡片),不用于内容本身。
- 统计页:
  - 背景使用柔和的渐变或带色彩的底,让玻璃有可折射的内容。
  - 图表(环形图、柱状图)保持高饱和、边界清晰。
  - 玻璃层用于顶部汇总卡片、月/年切换器、滚动时悬浮的周期选择条。
- 每个一级分类使用固定颜色,同时用于环形图、列表图标和账单页,保持整个 app 视觉统一。

## 10. CSV 导出

格式:

```
日期,类型,金额,一级分类,二级分类,备注
2026-10-10,支出,23.50,餐饮,午餐,"牛肉面, 加蛋"
```

- 编码为 UTF-8 带 BOM,保证 Excel 和 Numbers 打开不乱码。
- 含逗号、引号、换行的字段按 RFC 4180 加引号转义。
- 日期为 `yyyy-MM-dd`,金额为不带符号的两位小数,类型为"支出"或"收入"。
- 无二级分类时,二级分类列留空。
- 通过系统分享面板保存或发送。
- 文件格式预留为将来的导入功能使用,v1 不实现导入。

## 11. 错误处理

- SwiftData 保存失败时弹出明确提示,不静默丢数据。
- 记账页的输入合法性由键盘约束保证,保存时只校验"金额大于 0"。
- 删除操作提供撤销。
- 导出失败时给出提示。

## 12. 测试方案

使用 Swift Testing,重点覆盖纯逻辑:

- **金额**:分与字符串的互转;数字键盘输入规则(两位小数、上限、前导零)。
- **CSV 生成**:表头与字段格式;引号、逗号、换行转义;BOM。
- **统计聚合**:月汇总;按一级分类占比并带二级明细、"未细分"归并;按日和按月趋势;月底与跨月边界。
- **分类规则**:两层限制;归档一级分类时二级分类一并归档。

界面部分 v1 不写自动化 UI 测试,按手动清单在模拟器和真机上检查。

## 14. 分类管理与自定义图标

### 14.1 预置分类

只在库里还没有任何分类时写入。一级分类的顺序即显示顺序(先是作者常用的,后是通用的);二级分类继承一级分类的颜色。

| 一级(图标 · 颜色) | 二级 |
|---|---|
| 日用(`basket.fill` · #34C759) | — |
| 餐饮(`fork.knife` · #FF9F0A) | 早餐、午餐、晚餐、零食 |
| 交通(`bus.fill` · #0A84FF) | 公交地铁、打车 |
| 宠物(`pawprint.fill` · #A2845E) | — |
| 娱乐(`popcorn.fill` · #BF5AF2) | 电影 |
| 游戏(`gamecontroller.fill` · #5E5CE6) | 原神、ZZZ、steam、暴雪 |
| 旅游(`airplane` · #30B0C7) | — |
| 汽车(`car.fill` · #6C7A89) | 停车费、加油 |
| 其他(`ellipsis.circle.fill` · #8E8E93) | — |
| 服饰(`tshirt.fill` · #FF375F) | — |
| 购物(`cart.fill` · #D6336C) | 数码 |
| 居住(`house.fill` · #00A6A6) | 房租、水电燃气、网费 |
| 医疗(`cross.case.fill` · #FF453A) | 药品、诊疗 |

收入分类不变:工资、奖金、其他收入。

相对旧的预置,为避免与新增分类重复,去掉了这几个二级分类:购物·日用、购物·服饰(现在是一级的"日用""服饰"),娱乐·游戏、娱乐·旅行(现在是一级的"游戏""旅游"),交通·加油(现在是"汽车·加油")。

### 14.2 分类管理界面

入口:设置 Tab → 分类管理。

- 顶部"支出 / 收入"切换。列表显示该类型下所有未归档的一级分类,其二级分类缩进显示在下面;每行带图标、名称。
- 列表末尾有"已归档"分区,可以**恢复**。恢复一级分类时,它下面的二级分类一并恢复;被归档的一级分类下的二级分类不能单独恢复,需要先恢复一级分类。
- 点一行进入编辑页:**改名**、**上传 / 还原图标**、**归档**。
- 列表右上角"+":**新增一级分类**;一级分类的编辑页里有**新增二级分类**。
- 新增的一级分类从一组固定调色板里按顺序分配颜色;二级分类继承一级分类的颜色。v1 不提供自选颜色。

规则:

- 名称去掉首尾空白后不能为空,最长 10 个字符;同一个父分类(一级分类则是同类型下)里不能重名。重名和空名称在界面上直接提示,不保存。
- 归档沿用 §5 的规则:不物理删除,已有账单仍显示原分类名和图标;已归档分类不再出现在记账页的选择区和"常用"里。

### 14.3 自定义图标

- 在编辑页点"上传图标",用系统相册选择器选图。
- 处理方式:**居中裁成正方形,缩放到 128×128 像素,存成 PNG**。128 像素在 3 倍屏上显示成 46 点的圆圈已足够清晰;单张图最大约 66 KB(128×128×4 字节),不会撑大数据库。
- 限制:**原图超过 10 MB 直接拒绝**,提示"图片太大";无法解码的文件提示"无法读取这张图片"。
- "还原默认图标"把 `iconData` 清空,回到 SF Symbol。
- 显示:图标裁成圆形。出现在记账页的一级分类网格、账单页每一行(替代原来的色点)、分类管理界面。统计页暂不显示图标。
- 二级分类也可以上传自己的图标:它显示在账单页对应的行上(二级分类没有自己的图标时,用一级分类的图标)和记账页的二级分类标签上。
- 图片处理是纯函数,放在 Core 里,可以用 `swift test` 测。

### 14.4 测试补充

- **预置分类**:数量、层级、名称、顺序;没有重复的"一级 + 二级"组合。
- **图标处理**:裁成正方形、输出恰为 128×128、保留透明通道、超过 10 MB 被拒绝、坏数据报错。
- **名称规则**:去空白、空名称、超长、同级重名;不同父分类下允许同名二级分类。
- **归档/恢复**:恢复一级分类连带二级分类;二级分类不能在父分类归档时单独恢复。

### 14.5 数据迁移

`iconData` 是新增的可选字段,SwiftData 自动完成轻量迁移,已有账单和分类不受影响。预置分类只在空库时写入,所以已经装过旧版本的设备不会自动多出新分类,需要在分类管理里手动添加(作者的真机尚未安装旧版本,不受影响;模拟器里的旧数据通过删除 app 重装清除)。
