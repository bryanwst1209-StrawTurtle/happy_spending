# 账单查历史与长期使用不卡设计

日期:2026-10-22 · 项目:happy_spending
上位文档:`2026-10-10-bookkeeping-app-design.md`(账单页、统计页)、`2026-10-16-pending-categorization-design.md`(待归类)。冲突时以本文为准。

## 1. 目标与范围

两件事一起做:

1. **用 3~5 年不卡。** 实测(Mac、调试版):现在账单页每次刷新都把全部账单读出来再筛,每多用一年约多花 0.07 秒。用 3 年约 0.2 秒、5 年约 0.35 秒,搜索时每打一个字都要付一次,会明显卡顿。数据库本身很小(10 年约 4 MB),瓶颈在"每次都处理全部账单"。
2. **账单页能方便地查历史。** 默认仍是当前月;能直接跳到任意月份;搜索能搜全部历史。

**做:**

- 每个页面只从数据库读它要显示的那部分(§3)。
- 账单页、统计页点标题弹出年月(或年份)选择器;翻到当前月份 / 年份时 › 置灰;不在当前月时有"回到本月"(§4.1)。
- 账单页搜索加"本月 / 全部"范围;搜索也能按金额匹配(§4.2、§5)。

**不做:**

- 导出全部账单:以后作为 Pro 付费功能考虑。导出仍只有"导出本月"。
- 日期区间、金额区间等高级筛选。
- 账单页按年看月度汇总(统计页已覆盖)。
- 数据库结构不变,不做迁移。

## 2. 现状

| 地方 | 现在怎么取数据 |
|---|---|
| 账单页 | `@Query` 全部账单 → 全部转成行 → 在内存里挑当前月 |
| 待归类数量、页签角标、归类面板 | `@Query` 全部账单 → `PendingCategorization.pending` 挑出没分类的支出 |
| 编辑页、归类面板的"常用分类" | 全部账单的行 |
| 撤销删除时防重复 | 在全部账单里找同 id |
| 统计页 | `@Query` 全部账单 → 全部转成行 → 挑所选月份 / 年份 |

## 3. 只读需要的数据

| 地方 | 改成 |
|---|---|
| 账单页列表 | 只查所选月份:`date` 在 `[月初, 下月初)` 内,按日期倒序 |
| 待归类数量、页签角标、归类面板 | 只查 `category == nil` 的账,再在这一小批里挑支出、排序(`pending` 规则不变) |
| 编辑页、归类面板的"常用分类" | 最近 300 笔(按记账时间倒序,和记账页一致) |
| 撤销删除时防重复 | 按 id 查这一笔是否已存在 |
| 统计页 | 只查所选月份或年份的日期范围 |
| 年月选择器的年份范围 | 只取日期最早的一笔(取 1 条) |

查询条件放在 Core 里,以函数形式提供(返回 `FetchDescriptor` 或直接查询),界面层用它们构造 `@Query`,便于在内存数据库里测。

## 4. 交互

### 4.1 跳月份(账单页、统计页)

- 点标题(账单页"2026年10月"、统计页月视图的"2026年10月"或年视图的"2026年")从底部弹出选择器:
  - 月视图:年份、月份两列滚轮;年视图:只有年份一列。点"完成"跳过去,点"取消"或下滑不变。
  - 年份从**最早一笔账所在年**到**今年**;没有账时只有今年。今年的未来月份不可选。
- 两边的 ‹ › 保留;已经是当前月(或今年)时 › 置灰,不能翻到未来。
- 不在当前月(或今年)时,标题下方出现小按钮"回到本月"(年视图为"回到今年")。
- 打开 app 默认当前月,和现在一样。

### 4.2 搜索范围(账单页)

- 搜索框下方加范围选项"本月 / 全部",默认"本月"。
- **本月**:在当前所选月份里搜,和现在一样,另外支持金额匹配(§5)。
- **全部**:搜所有月份。
  - 停止输入约 0.3 秒后才查;搜索词为空时不查。
  - 结果按月份分组,组标题"2025年3月",右侧是该组匹配到的支出小计。
  - 最上面一行"找到 N 笔 · 支出 ¥X"。
  - 搜"全部"期间隐藏月份切换和收支汇总;清空搜索或切回"本月"后恢复。
  - 结果里点一笔打开编辑页,左滑删除;删除后照样可以撤销。改了日期、分类后结果立即更新。
  - 没有结果时显示系统的"无结果"页。
- 切换"本月 / 全部"时搜索词保留;"本月"模式下跳到别的月份,用同一个词在新月份里搜。
- "待归类 N 笔"入口在任何模式下都保留。

### 4.3 空状态

- 翻到当前月且没有账:"本月还没有账单"(不变)。
- 翻到历史月份且没有账:"这个月没有账单"。

## 5. 搜索匹配规则

一笔账满足任意一条就算匹配(不区分大小写,去掉首尾空白):

1. 备注包含搜索词。
2. 一级分类名或二级分类名包含搜索词。匹配到一级分类时,它下面所有二级分类的账也算。
3. "未分类"包含搜索词时,所有没有分类的账也算。
4. **金额**:搜索词能解析成金额时(复用 `AmountText` 的解析,允许 `¥`、`元`、千分位):
   - 带小数(`147.7`、`147.70`):金额恰好相等(¥147.70)。
   - 整数(`147`):金额在 `[147.00, 148.00)` 之间。
   - 0 或解析不了:不按金额匹配。

"全部"的实现:备注和金额交给数据库查;分类名先在分类列表(几十个)里找出匹配的分类,再取它们的账;几路结果按 id 去重,按日期倒序。"本月"在当月的行里用同一套规则过滤(`BillsLogic.search` 加上金额匹配)。

## 6. 测试方案

Swift Testing,SwiftData 用内存数据库。

- **查询**:
  - 月份查询只返回该月的账(含月初、不含下月初)。
  - 待归类查询只返回没分类的支出,顺序与 `pending` 相同。
  - 最近 300 笔查询按记账时间倒序、最多 300 笔。
  - 最早一笔查询返回日期最早的账,没有账时为 nil。
  - 年 / 月区间查询只返回该区间的账。
- **搜索**:
  - 备注、一级分类名(含其二级分类的账)、二级分类名、"未分类"。
  - 金额:`147.7`、`147.70`、`¥147.70` 只匹配 ¥147.70;`147` 匹配 ¥147.00~¥147.99,不匹配 ¥14.70、¥1470.00;`0`、`abc` 不按金额匹配。
  - 多路命中同一笔只出现一次;按日期倒序;空搜索词返回空。
  - "本月"的 `BillsLogic.search` 同样支持金额。
- **按月分组**:分组顺序从新到旧,每组支出小计正确。
- **年月选择器范围**:最早年份到今年;今年的未来月份不可选;没有账时只有今年。
- **性能**:用 5 年数据(约 18,000 笔)实测账单页每次刷新、待归类数量、统计年视图、搜"全部"一次的耗时,记录在计划执行结果里;目标是日常刷新在 50 毫秒以内。
- **模拟器**:点标题跳月份、› 置灰、回到本月、搜全部(含金额)、在结果里编辑和删除撤销、统计页跳年份。
